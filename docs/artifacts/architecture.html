  gc --> vault
  • Orchestrator: creates the run, fixes the step template for the mode, opens a ClaudeSDKClient with the mode prompt, streams model text as message.delta, maps tool calls to run_step rows and checklist events. Model output for cards is structured (pydantic-validated JSON blocks); the UI draws cards, the model never writes layout.
  • SDK options (main agent): mcp_servers={"hamkar": sdk_server}, allowed_tools=["mcp__hamkar__*"], built-ins disallowed (Bash, Read, Write, Edit, WebFetch, WebSearch), setting_sources=[] (no user CLAUDE.md), can_use_tool=gate, max_turns per mode (deploy 40, incident 30).
  • Tool registry: every tool is a typed async function with @hamkar_tool(name, group, risk). The decorator registers it with the SDK MCP server, records tool_call rows, runs the redactor on output, converts known API gaps into Limitation results, and for sensitive tools re-checks the approval.
  • Vault: decrypts the token for one call, passes it to the client, drops it. Tokens are never arguments of any tool and never part of a tool result.
  • SRE engine: turns evidence into signals (sre/signals.py), scores hypotheses (sre/ranking.py), and attaches success criteria to each proposed action (sre/criteria.py). The model explains and may re-order with a stated reason; scores and criteria stay deterministic.

11Code conventions

  • Python: 3.13, uv, ruff (lint + format), mypy strict on tools/, runtime/, core/; async everywhere (httpx.AsyncClient, SQLAlchemy 2 async, asyncpg); pydantic v2 models for every tool input/output and SSE payload.
  • Tools: one function per tool, @hamkar_tool(name, group, risk); returns Ok[T] | Limitation | ToolError; never raises for an API gap; never takes or returns a secret.
  • Errors: stable code (snake_case) + message_fa for the UI + English detail for logs.
  • Persian strings: in messages_fa.py / web/src/lib/fa.ts, not inline; digits stored ASCII, rendered Persian; dates stored timestamptz UTC, rendered Jalali.
  • Money: integer toman (bigint), formatted only in the UI.
  • Data on screen: every metric value is {value, source, observed_at}; the UI refuses to render a bare number.
  • TypeScript: strict; server components by default, client components only for chat/SSE; API types generated from the agent's OpenAPI.
  • Ids: UUIDv7. Migrations additive only.
  • Shortcuts carry # shortcut: <limit>, <when to upgrade>.
  • Commits: small, imperative; make check in the pre-push hook.

14Data model summary

Full ERD, columns and indexes: **DATA-MODEL.md**. Entities, grouped:

GroupEntities
Identity and connectionsuser, liara_connection, github_connection
Projectproject, repo_analysis, plan_proposal, deployment, domain
Conversation and runsconversation, message, run, run_step, tool_call, approval
SREincident, evidence, hypothesis, incident_action, verification, code_fix
Routinescheduled_check, check_result
Trustlimitation_event, audit_log
Qualityeval_case, eval_run

Key relations: a user has one liara_connection and one github_connection; a project has many deployment, domain, incident and conversation; a conversation has many message and run; a run has many run_step, each with many tool_call; a sensitive tool_call has one approval; an incident has many evidence and hypothesis, a hypothesis has many incident_action, each with zero or more verification; an incident_action of kind code has one code_fix; limitation_event and audit_log reference the tool_call that caused them.
